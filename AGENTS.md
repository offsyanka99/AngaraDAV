# AngaraDAV — Agent Instructions

Self-hosted CalDAV/CardDAV/WebDAV server (Baïkal-derived) with a TypeScript admin/user portal. See [README.md](README.md) for product overview, endpoints, and local Docker workflow — don't duplicate it here.

## Architecture

| Path | Role |
|------|------|
| [Core/Frameworks/Baikal/Core](Core/Frameworks/Baikal/Core) | Runtime bootstrap + DAV infra: YAML/PDO init, SabreDAV server setup, auth, plugins, files. `Baikal\Core\Bootstrap` owns project/config/runtime paths and opens SQLite or PostgreSQL. |
| [Core/Frameworks/Baikal/Portal](Core/Frameworks/Baikal/Portal) | **Active** portal JSON backend — auth, domain services/stores, install flow, admin services. This is where new server-side work goes. |
| [Core/Frameworks/BaikalAdmin](Core/Frameworks/BaikalAdmin) | Legacy compatibility scaffolding only. Its [README](Core/Frameworks/BaikalAdmin/README.md) says the old Formal web admin was removed; do not add new features here. |
| [html/](html) | PHP document root / front controllers: [dav.php](html/dav.php) (combined CalDAV+CardDAV+WebDAV), [cal.php](html/cal.php)/[card.php](html/card.php) (protocol-only), [api/index.php](html/api/index.php) (`/api/*` JSON for the SPA), `admin/index.php` (obsolete, redirects to `/portal/`). |
| [html/portal/](html/portal) | Generated Vite build output served at `/portal/` — never hand-edit; rebuilt by [portal/vite.config.ts](portal/vite.config.ts). |
| [portal/](portal) | TypeScript/Vite SPA source. See [portal/README.md](portal/README.md) for its internal conventions. |
| [Specific/](Specific) | Persistent runtime state (db, installer lock, logs, push state) — gitignored, not application code. |

## Admin API pattern

The Admin API lives in [Core/Frameworks/Baikal/Portal/App.php](Core/Frameworks/Baikal/Portal/App.php) (`App::handle()`), reached via [html/api/index.php](html/api/index.php). Every `/api/admin/*` route passes same-origin + CSRF checks, then `AdminAuth::requireAdmin()`, then `dispatchAdminRoutes()`. Business logic lives in focused services under [Core/Frameworks/Baikal/Portal/Admin](Core/Frameworks/Baikal/Portal/Admin) (`AdminUserService`, `AdminSettingsService`, `AdminBackupService`, etc.).

To add a new admin endpoint:
1. Put logic/validation in a `Baikal\Portal\Admin\*Service`; parse bodies via `HttpIO::jsonBody()`, throw `ApiException` for client errors.
2. Wire the route in `App::dispatchAdminRoutes()` — not in the front controller.
3. Audit every mutation with `AdminAudit`; never log secrets.
4. Add the typed client call in [portal/src/api/adminApi.ts](portal/src/api/adminApi.ts), exposed via [portal/src/api.ts](portal/src/api.ts).
5. Add a standalone PHP test following the pattern in [tests/php/AdminSettingsServiceTest.php](tests/php/AdminSettingsServiceTest.php).

## Conventions & compatibility traps

- PSR-0 autoload (see [composer.json](composer.json)): keep directory ↔ namespace alignment (`Baikal\Portal\...`, `Baikal\Portal\Admin\...`, legacy `BaikalAdmin\...`).
- Formatting is enforced repo-wide (except `vendor`) by [.php-cs-fixer.dist.php](.php-cs-fixer.dist.php) (`@PSR2` + `@Symfony`). Run `composer cs-fixer` to fix, or `php vendor/bin/php-cs-fixer fix --dry-run --diff --allow-unsupported-php-version=yes` to check.
- Do not change compatibility contracts called out in [README.md](README.md): `Baikal\*` namespaces, `BAIKAL_*` env vars, `baikal.yaml` schema, `/var/www/baikal`, DAV endpoint paths.
- [config/baikal.yaml.dist](config/baikal.yaml.dist) is the committed template; the live `config/baikal.yaml` is gitignored and generated by the installer/admin settings — never hand-edit or commit it.
- SabreDAV is patched post-install/update via [patches/README.md](patches/README.md) (`composer install` triggers `scripts/apply-vendor-patches.sh`); see [patches/sabre-dav-calendar-timezone.patch](patches/sabre-dav-calendar-timezone.patch) for why.

## Build, test, lint

Full detail in the [test-engineer agent](.github/agents/test-engineer.agent.md). Quick reference:

- `make php-test` — runs `tests/php/*.php` (standalone scripts, not PHPUnit).
- `composer phpstan` — static analysis; `composer cs-fixer` — auto-format. **`composer test` runs cs-fixer + phpstan, not the PHP tests.**
- `make portal` — `npm test` (Node's built-in `node:test`) + `npm run build` in [portal/](portal).
- `pytest tests/portal_admin_e2e.py -v` — live e2e against a disposable local instance only (`make local-up` first).
- `make local-up` — local Docker dev instance on `:31088`; see [README.md](README.md) for ownership/recreate pitfalls.
